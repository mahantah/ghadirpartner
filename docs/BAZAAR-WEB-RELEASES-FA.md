# مدیریت نسخه‌های اپ در اتوماسیون

مدیر از «تنظیمات سامانه ← مدیریت نسخه‌های اپ» می‌تواند فایل APK امضاشده را بارگذاری و با API رسمی پیشخان بازار ارسال کند. فرم‌ها از ابتدا باز هستند و بخش برای کاربران فروش، مالی یا مشتری نمایش داده نمی‌شود؛ کنترل سمت سرور نیز فقط نقش `admin` را می‌پذیرد.

## شروع کار

۱. در پیشخان بازار، برنامهٔ قدیر پارتنر را باز کنید؛ از منوی «API پیشخان بازار» یک توکن مخصوص همین برنامه دریافت کنید.
۲. توکن را در فرم اتصال وارد و ذخیره کنید. توکن ذخیره‌شده دوباره نمایش داده نمی‌شود. اگر توکن از متغیر محیط `CAFEBAZAAR_PISHKHAN_API_SECRET` خوانده شود، همان مقدار نسبت به فرم اولویت دارد.
۳. فایل APK امضاشده و توضیحات فارسی نسخه را انتخاب کنید. بارگذاری به صورت بخش‌های کوچک انجام می‌شود؛ پس از تکمیل، گواهی امضا، امضای دیجیتال کامل فایل، نام بسته، شماره نسخه و غیرقابل‌دیباگ بودن بررسی می‌شوند. کلید خصوصی امضا لازم نیست روی هاست قرار بگیرد.
۴. یکی از گزینه‌ها را انتخاب کنید:

| گزینه | نتیجه |
|---|---|
| ذخیره پیش‌نویس در بازار | فایل در رهانش آماده می‌شود؛ هنوز برای بررسی ارسال نمی‌شود |
| ارسال برای بررسی | درخواست بررسی با انتشار دستی پس از تأیید |
| بررسی و انتشار خودکار | درخواست بررسی؛ انتشار خودکار فقط بعد از تأیید بازار |

«بررسی وضعیت در بازار» صرفاً وضعیت پیش‌نویس، رهانش ارسال‌شده و نسخه منتشرشده را می‌خواند. اگر ارتباط قطع شد یا پاسخ قطعی نگرفتید، ابتدا وضعیت را بررسی کنید. سامانه پیش‌نویس نامرتبط را حذف یا جایگزین نمی‌کند و درخواست نوشتنی را خودکار تکرار نمی‌کند.

«حذف فایل محلی» فقط نسخه ذخیره‌شده روی هاست اتوماسیون را حذف می‌کند؛ سابقهٔ نسخه و وضعیت رهانش بازار تغییر نمی‌کنند. فایل APK اصلی را نزد خود نگه دارید.

## اطلاعات فنی برای نگهداری

- مسیرها: `GET/POST /api/admin/app-releases` و `POST /api/admin/app-releases/chunk`.
- تمام درخواست‌های نوشتنی با توکن CSRF همان نشست مدیر کنترل می‌شوند.
- تنظیمات محدودیت حجم و تعداد، زمان انتظار و نشانی‌های رسمی API در `config/bazaar-releases.yaml` هستند. این فایل YAML با زیرمجموعهٔ JSON نوشته شده تا به افزونه YAML در هاست نیاز نباشد.
- فایل‌ها و توکن در پوشهٔ مجزای `app-releases` کنار محل ذخیره وضعیت برنامه، با فایل PHP دارای `__halt_compiler` و پاسخ منع دسترسی نگهداری می‌شوند. داده‌های سفارش، مشتری و انبار نوشته نمی‌شوند.
- فقط امضای v2 از نوع RSA/SHA-256 با گواهی فعلی قدیر پارتنر پذیرفته می‌شود. نسخه‌های فعلی با همین روش امضا شده‌اند. این ابزار APK را ارسال می‌کند؛ مسیر AAB/BIN فعال نیست.
- استقرار، فایل‌های اصلی موجود روی هاست را با الحاق محدود تغییر می‌دهد؛ نسخهٔ عمومی و قدیمی `app.html`/`index.php` جایگزین سورس خصوصی نمی‌شود. بررسی پیش از استقرار شامل وضعیت کارتن‌های محافظت‌شده و قابلیت‌های PHP است و در خطا متوقف می‌شود.

مبنای پروتکل: [API پیشخان بازار](https://developers.cafebazaar.ir/fa/guidelines/feature/pishkhan-api)؛ مبنای کنترل امضا: [APK signature scheme v2](https://source.android.com/docs/security/features/apksigning/v2).
